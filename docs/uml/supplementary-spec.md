# Дополнительные спецификации FitSchedule

Версия 1.0 (09.11.2026). Подготовил Лесковский Е. Е., гр. 450501.

Документ содержит требования, которые не выражаются отдельными прецедентами модели
([`use-cases.md`](use-cases.md)), но ограничивают их выполнение. Классификация — FURPS+ (функциональность,
удобство использования, надёжность, производительность, сопровождаемость и ограничения). Источник требований —
SRS 0.2 ([`../srs/srs.md`](../srs/srs.md)); в столбце «Прецеденты» указано, к каким UC применяется требование.

## 1. Общая функциональность

| ID | Спецификация | Источник | Прецеденты |
|----|--------------|----------|------------|
| SUP-F-01 | Все операции, кроме регистрации, входа и просмотра расписания, требуют аутентифицированной сессии; сессия действует не более 7 суток | REQ-FUNC-002 | все, кроме UC-01, UC-03 |
| SUP-F-02 | Операции изменения расписания, слотов и чужих записей доступны только роли «Администратор» | REQ-FUNC-003, REQ-SEC-004 | UC-15…UC-18 |
| SUP-F-03 | Пользователь видит и изменяет только собственные записи, активность и уведомления; запрос чужого объекта возвращает 404 | REQ-SEC-003 | UC-08, UC-10, UC-13, UC-14 |
| SUP-F-04 | Создание, отмена и отклонение записи журналируются (время, событие, технический id) без персональных данных | REQ-OBS-001, REQ-SEC-005 | UC-05, UC-08, UC-09, UC-18 |
| SUP-F-05 | Все поля даты и времени хранятся в UTC и отображаются в часовом поясе клуба (Europe/Minsk) | SDD 003 | все |

## 2. Удобство использования

| ID | Спецификация | Источник | Прецеденты |
|----|--------------|----------|------------|
| SUP-U-01 | Интерфейс на русском языке, адаптивная вёрстка 360–1920 px без горизонтальной прокрутки | REQ-INT-001, REQ-COMP-002 | все |
| SUP-U-02 | После записи или отмены показываются результат и актуальное число свободных мест | REQ-INT-002 | UC-05, UC-06, UC-08 |
| SUP-U-03 | Ошибки ввода показываются текстом рядом с полем; пустые списки сопровождаются подсказкой | REQ-INT-005 | UC-01, UC-13, UC-15, UC-17 |
| SUP-U-04 | Отказ в записи всегда объясняет причину: нет мест (с предложением листа ожидания), пересечение (с конфликтующей записью), занятие недоступно | REQ-FUNC-008, 009 | UC-05, UC-07 |

## 3. Надёжность

| ID | Спецификация | Источник | Прецеденты |
|----|--------------|----------|------------|
| SUP-R-01 | При 100 одновременных запросах на последнее место создаётся не более одной записи | REQ-REL-001, ADR-0004 | UC-05, UC-09, UC-12 |
| SUP-R-02 | Отмена записи и продвижение листа ожидания выполняются одной транзакцией | REQ-FUNC-023, ADR-0006 | UC-08, UC-09, UC-18 |
| SUP-R-03 | При отмене занятия все его записи согласованно получают статус «Отменена клубом», очередь — EXPIRED | REQ-REL-003 | UC-16 |
| SUP-R-04 | Сбой необязательных частей (уведомления, экспорт .ics) не блокирует запись и отмену | REQ-INT-008 | UC-11, UC-19, UC-20 |
| SUP-R-05 | При сетевой ошибке клиент показывает сообщение и не теряет введённые данные | REQ-REL-002 | все |

## 4. Производительность

| ID | Спецификация | Источник | Прецеденты |
|----|--------------|----------|------------|
| SUP-P-01 | Расписание из 200 занятий за неделю загружается не более чем за 3 с | REQ-PERF-001 | UC-03, UC-04 |
| SUP-P-02 | Запись завершается не более чем за 2 с (95-й процентиль) при 50 параллельных запросах | REQ-PERF-002 | UC-05 |
| SUP-P-03 | Уведомление появляется у получателя не позднее чем через 60 с после события | REQ-FUNC-021, ADR-0005 | UC-14, UC-19 |
| SUP-P-04 | Напоминание создаётся за 2 ч до начала с точностью до 1 минуты, не более одного на запись | REQ-FUNC-022 | UC-20 |

## 5. Сопровождаемость

| ID | Спецификация | Источник | Прецеденты |
|----|--------------|----------|------------|
| SUP-S-01 | Правила записи (`BookingPolicy`) не зависят от web-слоя, покрытие тестами не менее 80 % строк | REQ-MAINT-002, ADR-0001 | UC-05, UC-07, UC-08 |
| SUP-S-02 | Модели UML хранятся в текстовом виде PlantUML рядом с документацией и изменяются через pull request | REQ-MAINT-001, ADR-0007 | — |
| SUP-S-03 | REST API описано спецификацией OpenAPI 3.0 по адресу `/v3/api-docs` | REQ-INT-006 | все |

## 6. Ограничения проектирования и реализации

| ID | Спецификация | Источник |
|----|--------------|----------|

| SUP-C-05 | Стоимость проекта — $0, выпуск 1.0 — 02.05.2027 | SRS 3.5.7, 3.5.8 |

## 7. Вне рамок версии 1.0

Кабинет тренера (REQ-FUNC-017), автоматический учёт посещённых занятий в истории активности (REQ-FUNC-020),
поиск по названию занятия, шаблон недели для слотов, графики активности, оплата, мобильные приложения, доставка
уведомлений вне сайта (e-mail, push). Эти функции не имеют прецедентов в модели 1.0.
