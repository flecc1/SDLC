# Глоссарий проекта FitSchedule

Версия 1.0 (09.11.2026). Подготовил Лесковский Е. Е., гр. 450501.

Глоссарий объединяет термины предметной области, термины модели UML и технические термины, которые используются
в SRS ([`../srs/srs.md`](../srs/srs.md)), SDD ([`../sdd/sdd.md`](../sdd/sdd.md)), ADR
([`../adr`](../adr)) и модели динамического поведения ([`use-cases.md`](use-cases.md),
[`diagrams`](diagrams)). Термины упорядочены по алфавиту внутри каждого раздела.

## 1. Предметная область

| Термин | Английский эквивалент | Определение | Где используется |
|--------|-----------------------|-------------|------------------|
| Администратор | Administrator | Сотрудник клуба, который ведёт расписание, вместимость, слоты тренеров и сроки отмены, может отменять занятия и записи посетителей | UC-15…UC-18, REQ-FUNC-003, 005, 006 |
| Вместимость | Capacity | Максимальное число посетителей, которые могут записаться на групповое занятие; целое число больше нуля | `training.capacity`, REQ-FUNC-005 |
| Групповое занятие | Training | Тренировка с фиксированными названием, временем, залом, тренером и вместимостью | UC-03, UC-05, `state-training` |
| Запись | Booking | Подтверждённое место посетителя на групповом занятии или в слоте тренера | UC-05, UC-08, `state-booking` |
| Зал | Hall | Помещение клуба, в котором проводится занятие | карточка занятия, REQ-INT-004 |
| История активности | Activity log | Список завершённых тренировок посетителя с датой, типом и длительностью | UC-13, REQ-FUNC-018, 019 |
| Конфликт (пересечение) | Overlap | Ситуация, когда интервалы двух подтверждённых записей одного посетителя пересекаются по времени | UC-07, REQ-FUNC-009 |
| Лист ожидания | Waitlist | Очередь посетителей на заполненное занятие; при освобождении места первый подходящий посетитель записывается автоматически | UC-06, UC-09, REQ-FUNC-023 |
| Напоминание | Reminder | Уведомление о предстоящем занятии, создаваемое за 2 часа до начала | UC-20, REQ-FUNC-022 |
| Отмена клубом | Cancellation by club | Отмена занятия администратором; все записи получают статус «Отменена клубом» | UC-16, REQ-FUNC-006, REQ-REL-003 |
| Персональная тренировка | Personal training | Индивидуальное занятие с тренером в забронированном слоте | UC-12, REQ-FUNC-014…016 |
| Посетитель | Visitor | Клиент клуба, зарегистрированный в системе; смотрит расписание, записывается и ведёт активность | UC-01, UC-05…UC-14 |
| Пользователь | User | Любое лицо, вошедшее в систему: посетитель, тренер или администратор | UC-02, UC-03 |
| Расписание | Schedule | Перечень групповых занятий за выбранную дату или неделю | UC-03, REQ-FUNC-004 |
| Свободные места | Free places | Разность вместимости и числа подтверждённых записей занятия | `training.free_places`, REQ-INT-002 |
| Слот | Slot | Интервал времени, в который тренер доступен для персональной тренировки | UC-12, UC-17 |
| Срок свободной отмены | Cancellation deadline | Число часов до начала занятия, до которого посетитель может отменить запись сам | UC-08, REQ-FUNC-011, 012 |
| Тренер | Trainer | Сотрудник клуба, ведёт групповые занятия и персональные тренировки | UC-02, UC-03 |
| Уведомление | Notification | Сообщение внутри приложения об отмене или изменении занятия либо о продвижении из листа ожидания | UC-14, UC-19, REQ-FUNC-021 |

## 2. Модель UML

| Термин | Английский эквивалент | Определение | Где используется |
|--------|-----------------------|-------------|------------------|
| Актёр | Actor | Роль, которую человек, внешняя система или время играет по отношению к системе | `use-case.puml` |
| Альтернативный поток | Alternative flow | Отклонение от основного потока прецедента при выполнении условия | `use-cases.md` |
| Включение | Include | Связь, при которой прецедент всегда выполняет поведение другого прецедента | UC-05 → UC-07 |
| Диаграмма активности | Activity diagram | Диаграмма поведения, показывающая поток действий, ветвления, параллельность и дорожки ответственности | `activity-*.puml` |
| Диаграмма последовательности | Sequence diagram | Диаграмма взаимодействия, показывающая упорядоченный во времени обмен сообщениями между линиями жизни | `sequence-*.puml` |
| Диаграмма состояний | State machine diagram | Диаграмма поведения, показывающая состояния объекта и переходы по событиям | `state-*.puml` |
| Дорожка | Swimlane (partition) | Часть диаграммы активности, закреплённая за исполнителем действий | `activity-booking.puml` |
| Комбинированный фрагмент | Combined fragment | Часть диаграммы последовательности с оператором `alt`, `opt`, `loop`, `break`, `ref` | `sequence-*.puml` |
| Линия жизни | Lifeline | Участник взаимодействия и ось его времени жизни на диаграмме последовательности | `sequence-*.puml` |
| Обобщение | Generalization | Связь «частное — общее» между актёрами или прецедентами | Посетитель → Пользователь |
| Основной поток | Basic flow | Нормальная последовательность шагов прецедента, приводящая к цели | `use-cases.md` |
| Постусловие | Post-condition | Состояние системы, которое гарантируется после завершения прецедента | `use-cases.md` |
| Предусловие | Pre-condition | Условие, которое должно выполняться до начала прецедента | `use-cases.md` |
| Прецедент | Use case | Последовательность действий системы в ответ на событие, инициированное актёром, приводящая к значимому для него результату | `use-cases.md` |
| Расширение | Extend | Связь, при которой прецедент дополняет другой только при выполнении условия в точке расширения | UC-06 → UC-05 |
| Сторожевое условие | Guard | Логическое условие в квадратных скобках, разрешающее переход | `state-*.puml`, `activity-*.puml` |
| Точка расширения | Extension point | Место в потоке прецедента, где может быть подключено расширение | UC-05 «нет свободных мест» |

## 3. Технические термины

| Термин | Определение | Где используется |
|--------|-------------|------------------|
| ADR | Architecture Decision Record — запись архитектурного решения в формате MADR | `docs/adr` |
| FOR UPDATE | Режим `SELECT`, блокирующий выбранные строки до конца транзакции | ADR-0004, `sequence-booking.puml` |
| iCalendar (.ics) | Формат файлов календарных событий (RFC 5545) | UC-11, REQ-INT-007 |
| PlantUML | Текстовый язык описания диаграмм UML, из которого генерируются изображения PNG/SVG | ADR-0007 |
| REST API | Программный интерфейс поверх HTTP с ресурсами и JSON | SDD 004 |
| SDD | Software Design Description — описание дизайна ПО (IEEE 1016) | `docs/sdd/sdd.md` |
| Short polling | Периодический запрос клиента к серверу (раз в 60 с) | ADR-0005, UC-14 |
| SPA | Single Page Application — клиент в браузере, работающий через REST API | ADR-0002 |
| SRS | Software Requirements Specification — спецификация требований | `docs/srs/srs.md` |
| SysML v2 | Язык системного моделирования; используется для структурных моделей SDD | `docs/sdd/models` |
| Транзакция | Группа операций с БД, выполняемая целиком или не выполняемая совсем | ADR-0004, ADR-0006 |
